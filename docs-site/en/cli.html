gyro CLI

gyro: manage Gyro Hosting services from your terminal.

A single binary for Linux, macOS and Windows (amd64, arm64). Release checksums are signed with the Gyro release key (E96B E963 5E77 A0D9 119A C8C3 A798 6589 A154 B990).

Getting started

gyro configure                     # API key: Client area → Account → API
gyro whoami
gyro plan list --location falkenstein
gyro server create web-1 --plan pro-2-8 --location falkenstein --image ubuntu-24.04 \
     --ssh-key ~/.ssh/id_ed25519.pub --wait
gyro server ssh web-1

Ordering shows the API price quote first, asks for confirmation and pays from your balance. --wait blocks until the server runs.

Profiles and credentials

  • gyro configure [--profile name] checks the key and writes ~/.config/gyro/config.toml (mode 0600); --keyring uses the OS keychain.
  • Scripts: echo "$KEY" | gyro configure --token-stdin --profile ci or just GYRO_TOKEN.
  • Precedence: flag > environment (GYRO_TOKEN, GYRO_PROFILE, GYRO_API_URL, GYRO_OUTPUT, GYRO_LANG) > profile.
  • gyro context shows the active profile and key permissions; gyro context use name switches the default.

Output and scripting

  • -o table|json|yaml|text, --query (JMESPath), -q ids only, --no-header, --wide.
  • Colours only on a terminal; NO_COLOR disables them. Language from the locale or --lang tr|en.
  • Names or ids: gyro server get web-1 equals gyro server get 47485.
  • Shell completion: gyro completion bash|zsh|fish|powershell (server and key names complete from the API).

Safety: confirmation, dry run, idempotency

  • Money and destructive actions ask for confirmation; use --yes in scripts. Without a terminal and without --yes the command refuses to run (exit code 7).
  • --dry-run shows the price quote (where supported) or the request that would be sent; nothing changes.
  • Money operations carry an automatic Idempotency-Key: re-running never orders twice.
  • Safe requests are retried with backoff on 429/5xx. Errors show the API code, HTTP status and request id.
Exit codeMeaning
0success
2usage error
3authentication / permission (401, 403)
4not found
5conflict (409)
6payment
7not confirmed
8rate limited
9--wait timeout

Every product

Mail, S3, monitors, licences, VDS, dedicated servers and apps use the same bridge. Tools and actions are read from the service, so new features work without a CLI update:

gyro mail list
gyro mail tools example.com                       # tools, actions, confirm/secret policy
gyro mail mailbox create example.com --set local_part=info --set password=@-
gyro s3 bucket list mystorage
gyro license status 48001
gyro service tool run 48001 <tool> <action> --set field=value
